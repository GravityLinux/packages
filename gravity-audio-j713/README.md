# J713 audio add-on

`gravity-audio-j713` adds MacBook Air 13" (M4, J713) support to Fedora's
`alsa-ucm-asahi`, `asahi-audio` and `speakersafetyd` without changing them.
Every file goes into a directory those programs already read, so Fedora's
updates of the three packages reach users unchanged.

| File | Read by | How it is found |
| --- | --- | --- |
| `alsa/ucm2/conf.d/macaudio/MacBook Air J713.conf` | alsa-lib UCM | `conf.d/<driver>/<card long name>.conf` |
| `alsa/ucm2/conf.d/macaudio/j713/HiFi.conf`, `Headphones.conf` | alsa-lib UCM | the J713 card file's verb: alsa-ucm-asahi's `laptops/HiFi.conf` (speakers) plus a headphone-only jack device |
| `alsa/ucm2/conf.d/aop_audio/MacBook Air J713 High-Power Audio Interface.conf` | alsa-lib UCM | as above; uses alsa-ucm-asahi's `3chan/HiFi.conf` |
| `wireplumber/wireplumber.conf.d/99-asahi-j713.conf` | WirePlumber 0.5 | conf.d fragment; its `node.software-dsp.rules` are appended to asahi-audio's |
| `asahi-audio/j413/graph-j713.json`, `mic-j713.json` | WirePlumber `create-filter` | generated by an RPM trigger from asahi-audio's J413 graphs, with asahi-audio's own alias rule (the one that makes the J613 graphs) |
| `speakersafetyd/apple/j713.conf` | speakersafetyd | `<config dir>/<maker>/<model>.conf` from the device-tree compatible |
| `udev/rules.d/95-speakersafetyd-j713.rules` | udev | starts speakersafetyd for the `AppleJ713` card |

The speakersafetyd profile reuses the J413/J613 thermal model with t_limit 130 C
on every speaker; see the comment in `speakersafetyd-j713.conf`. The headphone
DAC mapping is the J413/J613 one and still needs a listen test.

## Versions

Written against alsa-ucm-asahi 10, asahi-audio 4.1 and speakersafetyd 2.0.1
(Fedora 44). What a Fedora update can break:

- alsa-ucm-asahi: renaming or restructuring `laptops/HiFi.conf` (the J713 verb
  includes it) or `aop_audio/3chan/HiFi.conf`.
- asahi-audio: moving the J413 graphs out of `j413/graph.json` and
  `j413/mic.json`. The trigger then leaves the last generated graphs in place.
- Any of the three adding its own J713 files: the RPM file conflict stops the
  update, and this package should drop the overlapping part. For asahi-audio
  there is no file conflict (it would add rules, not our files): check
  `99-asahi.conf` for `AppleJ713` when asahi-audio is updated, or the J713 would
  get two filter chains.

## Replacing the forks

The 20261110 release packaging added same-named forks of the three packages
(releases `10-100..102.gravity`, `4.1-100..101.gravity` and
`2.0.1-100.gravity`); they never reached COPR but are installed on test
machines. Their
releases sort above Fedora's, so dnf would keep them forever once the Gravity
repository stops carrying them. This package obsoletes each of those builds
by exact version, so a plain `dnf upgrade` that brings it in (through
`gravity-platform-metapackage-audio`) removes the forks and installs Fedora's
builds in the same transaction. A Conflicts on the forks' `gravity-*`
capabilities is kept as a guard; on its own it only made dnf skip this
package. Add an Obsoletes line here for any other fork build that reached a
machine.

## Safety

speakersafetyd must hold and refresh the macaudio unlock control before the
amps leave their lowest volume step. Validate the profile, sense scaling and
failure behaviour on the matching kernel before a release. Package tests must
not activate hardware or start the daemon.
