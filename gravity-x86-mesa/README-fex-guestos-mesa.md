# fex-guestos-mesa

The x86 system tree that Valve's FEX compatibility tool for ARM64 Steam
(app 3127680, "FEX") expects at `/usr/share/guestos/fex-mesa`. The tool
hardcodes that path and uses it twice:

- **FEX root filesystem.** FEX runs the Steam Linux Runtime's `#!/bin/sh`
  entry point from here before it re-executes natively through
  `aarch64-linux-gnu-exec`.
- **pressure-vessel graphics provider.** Its `graphics_provider.json` is
  exported as `STEAM_COMPAT_GRAPHICS_PROVIDER`, so pressure-vessel imports the
  x86 OpenGL, EGL, GBM and Vulkan drivers and their dependencies, down to
  glibc, into the game's container. See steam-runtime-graphics-provider.json(5).

Without this tree, native Linux x86 games exit with no window ("RootFS path
doesn't exist").

## Layout

The layout is Arch-style, as in Valve's documented example:

- x86_64 in `usr/lib`, i386 in `usr/lib32`.
- `lib`, `lib64` and `usr/lib64` link to `usr/lib`; `lib32` links to
  `usr/lib32`.
- `bin`, `sbin` and `usr/sbin` link to `usr/bin`.

A Fedora-style tree (x86_64 in `lib64`) collides with the ARM64 host's
`lib64` in Valve's tool. `etc/ld.so.cache` covers both architectures and is
generated with the tree's own `ldconfig`.

## Where the files come from

`MANIFEST.json` (installed in the package's doc directory) names the source of
every file: `fedora:<NEVRA>`, `mesa:<commit>:<arch>` or `generated`.

| Part | Source |
|---|---|
| glibc, libgcc, libstdc++, libglvnd, libdrm, X11/xcb, Wayland client, expat, zlib, zstd, libffi, libdisplay-info, SPIRV-Tools, libudev | Fedora 44 x86_64 and i686 packages (`mesa-fex-guest/guestos-packages.txt`): shared libraries and glibc's `gconv` only |
| `usr/bin/bash` (`sh`), `usr/bin/busybox` (`readlink`, `date`, `getopt`, `env`), `usr/bin/ldconfig` | Fedora 44 x86_64 `bash`, `busybox` and `glibc` |
| Mesa: `libgallium`, `libGLX_mesa`, `libEGL_mesa`, `libgbm`, `dri/`, `gbm/`, `libvulkan_asahi`, ICD and EGL vendor JSON, `drirc.d` | x86_64 and i686 builds of the system Mesa's pinned source |
| `usr/share/licenses` | The Fedora packages' license texts |
| `etc/ld.so.conf`, `etc/ld.so.cache`, `graphics_provider.json`, directory links, the Vulkan ICD `library_path` edits | Generated by `mesa-fex-guest/assemble.py` |

The package list is the dependency closure of our Mesa and libglvnd, plus
bash. `assemble.py` fails if any ELF file has a `NEEDED` library missing from
its architecture's directory.

## Building

Nothing is compiled in this package. COPR builds `mesa-fex-guest` in the
`fedora-44-x86_64` chroot: Mesa from the `mesa` source pin, with the Fedora
packages above installed as build dependencies from Fedora's repositories,
and `assemble.py` puts this tree together there. `gravity-x86-mesa`, whose
SRPM carries that RPM (pinned by URL and SHA256 with `make pin`), installs
the tree as this subpackage. Rebuilding `mesa-fex-guest` picks up Fedora
updates of the libraries; `MANIFEST.json` records which versions shipped.

The x86 and ARM64 drivers come from the same commit: `Requires:
gravity-mesa-revision = <commit>` only installs with the matching system Mesa.

## Outside Steam

`gravity-x86` runs x86 programs with Fedora's x86 root filesystem
(`fex-emu-rootfs-fedora`), whose Mesa 26.0 cannot submit to the G16 GPU
(`DRM_IOCTL_ASAHI_SUBMIT` fails, so windows stay blank).

This tree also works as that root filesystem: with
`FEX_ROOTFS=/usr/share/guestos/fex-mesa`, i386 and x86_64 glxgears render on
the GPU through gravity-x86. But it holds only the graphics stack's closure,
not a general x86 userland. For example, Super Crate Box's runner also needs
openal, Xrandr, GLU and OpenSSL, which are in Fedora's 3.4 GB root filesystem
but not here. Making it the default root filesystem would break most other
x86 programs.

Outside Steam, gravity-x86 instead mounts Fedora's root filesystem with the
same x86 Mesa revision, built in Fedora's layout (lib64/lib), over it
(`gravity-x86-mesa`).
